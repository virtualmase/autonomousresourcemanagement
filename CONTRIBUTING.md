# Contributing to the ARM Reference Layer

Thank you for improving the cited definition and research material for Autonomous Resource Management. This repository is a **reference property**, not a catch-all marketing site, commercial product, or agentic portal.

## Before you contribute

Use GitHub Discussions for questions, conceptual debate, source discovery, and proposed directions. Use Issues only for work that can be described, reviewed, and closed: a factual correction, a missing source, an accessibility defect, a broken link, or a scoped documentation improvement.

Every contribution must state the property it affects, the reader it serves, the source or provenance for factual claims, and whether it changes the shared entity registry. Do not copy text from another ARM property merely to increase repetition. Each property earns its authority by making an original contribution.

## Review expectations

Contributors should keep changes small and explain why they improve accuracy, clarity, accessibility, or source quality. Changes to definitions, structured data, entity relationships, public property roles, security guidance, or outward claims require review by two maintainers, including the relevant property steward.

Do not include private customer material, credentials, personal information, unverified performance claims, legal conclusions, or claims of certification/compliance. Use accessible HTML, describe meaningful images accurately, and leave decorative images with empty alternative text.

## Local preview

This is a no-build static site. Preview with any standards-compliant static file server or open the HTML directly in a browser. Before proposing a change, check the rendered headings, links, structured data, mobile behavior, and HTML semantics.

## Contribution lifecycle

1. Open a Discussion if the scope, source, or property boundary is unclear.
2. Open a structured Issue for agreed work.
3. Submit a pull request linked to that Issue, including sources and a short impact statement.
4. Maintainership reviews the change, records the decision where material, and merges only after approvals are complete.
